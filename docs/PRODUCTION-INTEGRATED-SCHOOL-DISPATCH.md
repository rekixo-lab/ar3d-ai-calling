# Integrated production School calling and CRM import mapping

This batch implements a current-MFA Super Admin bulk calling authorization for up to 50 exact reviewed School jobs, shared funding admission, durable one-use dispatch claim, server-owned School session creation, existing Plivo POST adapter, signed callback recovery, bounded automatic settlement and terminal capacity release, tenant result read API, dashboard controls and privacy inventory. Funding-only approval and old prepared jobs never dial. The production template now explicitly enables the School dispatch feature (AR3D_INDUSTRY_SCHOOL_DISPATCH_ENABLED=enabled); no new variable edit is needed for this switch. It does not alter provider credentials or independently required approvals. Existing School voice, funding, provider disclosure and automatic CDR settlement approvals are also required. Recovery is considered with new dispatch disabled. Unknown POSTs are never retried or assumed free; expired funded releases that provably never POSTed and definite rejected sessions with no carrier identifiers can release an exact unused hold. Ambiguous funding admissions remain locked for review. The existing minute trigger alternates bounded industry work with property work, rotating funding, dialing and recovery. This conserves D1 queries; it is not a high-throughput or real-carrier acceptance claim.

CSV/XLSX imports support bounded header inspection and explicit index mapping to existing allowlisted CRM contact fields; automatic header aliases remain compatible. Preview and commit use the exact map. Import never grants consent or financial-account authorization. School results show accepted bounded answers and verified billed/connected seconds, no raw transcript or provider monetary cost.

Finance, Banking and Insurance remain non-callable drafts, because simulation is not identity verification or an authorized account data source. Appointment-specific announcement runtime is not yet implemented. Fresh review/re-preparation after an already completed immutable job remains conservatively blocked. Migration 0030 is additive and guarded. Synthetic automated fixtures only; no staging, live customer calls, paid TTS or real wallet operations. Merge only after exact-head CI.

## Client Admin calling

Active client admins may explicitly release their own previously reviewed School jobs directly from the client dashboard. The current session, actual database role and same-tenant active membership are checked before readiness or writes and rechecked after configuration reads. Existing Super Admin MFA remains required for the Super Admin route, separate funding-only approval, launch/audio review and recipient clearance. Funding and dispatch retain a durable actor ID and recheck active authority. A lost client membership before funding prevents reservation; after funding, a still-authorized (never posted) job may release only its exact unused hold. Logging out does not cancel an already explicitly authorized short-lived batch, but prevents new releases from that session. Already placed calls must still settle if the actor is removed. No unrelated client, viewer, trial/suspended tenant or unreviewed recipient gains access. The explicit confirm shows maximum wallet minutes across selected jobs. The server validates selected duration and expiry. School recording beeps are disabled; the preceding AI/recording disclosure and opt-out remain intact. No live customer calls or paid operations are used in synthetic tests. The existing bounded scheduler is not a guarantee that all 50 jobs complete within one hour.

## Shared trusted notice service integration

The four remaining notice templates share a server-only connector adapter (`src/industry-notice-connectors.mjs`). The Worker expects independent `INDUSTRY_NOTICE_RECORD_SERVICE` and `INDUSTRY_NOTICE_IDENTITY_SERVICE` service bindings and the Worker secret `AR3D_NOTICE_ISSUER_KEYS_JSON`, an array of objects containing tenantId, identityKeyHex and recordKeyHex. Signer keys must be distinct across tenants and issuers. Never put real keys in GitHub, client UI, logs or ordinary CRM imports. Fixed internal endpoints POST `/v1/approved-notice` and `/v1/recipient-proof` return the signed envelope defined by `industry-verified-notice.mjs`. Identity requests include scope and verified record digest, never record fields. Bounded JSON, strict signatures, manual redirects, freshness and repeated scope checks fail closed. The dashboard reports configuration availability only. No actual binding or secret has been configured or verified; no call or disclosure authorization is created. The future carrier callback must supply server-owned active-call scope, purpose-specific clearance, live consent and held wallet, then atomically consume a one-use disclosure permit before speech. Production launch, queue, session creation, private speech and settlement remain unimplemented for these four templates. Tests use fictional signed envelopes and mocked bindings only.
