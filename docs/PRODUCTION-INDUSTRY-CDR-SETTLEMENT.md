# Production industry CDR settlement foundation

The shared CRM gains an immutable purpose-aware industry CDR receipt table, keyed by the exact tenant, funded job, session, provider request and call UUID. It stores bounded provider-reported amounts without asserting currency. It never stores the dialed number, raw provider response or transcript. It rejects property job/call collisions and duplicate identities.

The internal settleIndustryCallCdr adapter requires the immutable funded admission and historical recipient review, exact server-owned School session and manifest digest, matching shared minute/provider reservation, signed-ended terminal phase and at least 60 seconds after hangup. It reads an identity-matched Plivo CDR using the shared bounded GET helper. Evidence is recorded before closing the existing hold. Conflicting receipts, unavailable CDRs, non-30-second pulses and charges above the reserved amount do not release held credit. Retrying identical evidence after a cross-database failure is idempotent. Historical consent revocation, archive and audio removal do not invalidate financial evidence; they still block new calls.

No route or cron invokes this adapter yet. No carrier POST, automatic dialing, real provider call, actual wallet reservation/debit, provider-money reconciliation, capacity release, or staging resource is introduced. Capacity deliberately remains occupied until a separate audited terminal lifecycle is implemented. A future dispatcher must add separate release authorization, durable claim and session creation; a future scheduler must bound CDR work and reconcile terminal capacity and results.
