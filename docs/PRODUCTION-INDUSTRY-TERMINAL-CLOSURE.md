# Production terminal capacity recovery foundation

This phase adds an append-only industry terminal closure in the shared CRM. A separate server-only operation checks the exact historical funded admission, recipient and server-owned signed-ended School session, the immutable verified CDR, and the same immutable settled Control D1 hold. It requires the exact Plivo evidence reference and charged seconds; unavailable, inconsistent, unsupported or uncertain evidence keeps capacity occupied. It makes no provider request and never mutates the wallet. A failed or interrupted closure can be replayed without another provider read or wallet charge. The receipt and closure are bound by a CRM trigger; the cross-D1 hold is validated by trusted server code, not by the CRM trigger itself.

The shared capacity dashboard, property scheduler snapshot, atomic global/per-tenant admission and cross-purpose active-lead exclusion use the same closure-aware SQL predicate. Confirmed closed slots no longer consume capacity. This does not grant a new consent or clearance to a property job. The immutable School preparation/admission remains single-use and cannot be cancelled, re-prepared or dialled again. Queue history reports settled/closed separately from preparation, without exposing billing evidence or phone numbers. Privacy dependency inventory includes closures.

Migration 0029 is additive, exact-prior-schema guarded and checked before Worker deployment. No new route, scheduler invocation, provider POST, live call, real provider request, production wallet mutation or staging resource is added. Unknown funding claims, unknown submission, expired jobs without terminal evidence and no-submission recovery deliberately remain locked. A separate durable dispatch release/claim and session creator must be implemented before actual School calling, followed by bounded automatic reconciliation. Real carrier interoperability and retention remain unverified. Synthetic local fixtures and mocked provider responses only. Merge only after #237 production success and exact-head CI.
