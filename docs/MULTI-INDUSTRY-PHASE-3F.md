# Phase 3F — Cloudflare locked School staging deployment

This is deployment tooling, not a completed Cloudflare deployment or a phone test.
It never modifies production names/configuration and never creates or dials a
recipient. Existing production deploy workflow remains unchanged.

## One-time resources

In Cloudflare, create a NEW empty D1 database named
`ar3d-calling-school-stage-control`, and NEW private R2 bucket
`ar3d-calling-school-stage-audio`. Keep r2.dev and custom domains disabled.
Do not copy production records or credentials. Use dedicated least-privilege
Cloudflare stage credentials; set up the Workers.dev subdomain for the account.
The separate Worker name is `ar3d-ai-calling-school-stage`. The origin must be
`https://ar3d-ai-calling-school-stage.<account-subdomain>.workers.dev`.
The script refuses different physical D1 names, known production D1 IDs, existing
unmarked databases, legacy schema, public R2, and wrong worker origins.

In GitHub create protected environment **school-stage** with required reviewer
and only main allowed. Set these environment secrets (never paste into chat):

- SCHOOL_STAGE_CLOUDFLARE_ACCOUNT_ID, SCHOOL_STAGE_CLOUDFLARE_API_TOKEN
- SCHOOL_STAGE_D1_ID (new D1 UUID)
- AR3D_MAIN_CONTROL_DB_ID and AR3D_MAIN_CRM_DB_ID (IDs only; comparison guard)

Set environment variables SCHOOL_STAGE_ORIGIN (exact workers.dev URL) and
SCHOOL_STAGE_TENANT_ID (new UUID v4 generated by the operator). The workflow uses
no production token, provider credentials or customer phone numbers. Require
explicit approval on workflow runs and review resource identifiers in Cloudflare.

## Deploy locked

After review/merge to main, open Actions → AR3D School Stage - locked manual
deployment, choose **preflight**, confirmation SCHOOL_STAGE_ONLY. This verifies
remote D1 identity/private R2 and builds the stage entrypoint without deployment.
Then explicitly select **deploy_locked** with the same confirmation to apply the
allowlisted auth + school migrations with Wrangler's migration history (including
an immutable stage marker), recheck resources, deploy a locked Worker and smoke
test health/unauthenticated dispatch/legacy-route isolation.

All stage live, approval, audio and bootstrap flags default to disabled. There
is no push/PR/cron trigger. The workflow neither provisions resources nor
configures provider secrets. The production Worker will not use these routes.
Do not run locked redeploy while an existing pilot is active; it intentionally
resets switches to disabled. Hangup evidence and carrier-side stop still depend
on provider configuration. Real staging resource IDs and deployment need
authorized operator access; tests use mocks and SQLite.

For local authorized execution from a clean checkout, set the same stage inputs
as the workflow (CLOUDFLARE_ACCOUNT_ID/TOKEN mapped to the dedicated stage
credentials, PRODUCTION_CONTROL_DB_ID and PRODUCTION_CRM_DB_ID for comparison).
Then run `node scripts/school-stage-cloudflare.mjs prepare`, use the generated
`wrangler.school-stage.generated.json` for the named stage migrations/dry-run/
deployment only, and verify-ready before deploy. Never commit generated config
or migrations directory. No remote commands run in regular CI.

## Initialize fictional operator flow (while all paid flags remain disabled)

Configure independent stage auth secrets MFA_ENCRYPTION_KEY,
and LOGIN_RATE_LIMIT_SECRET as required by existing auth.
Set a random stage-only AR3D_SCHOOL_STAGE_BOOTSTRAP_TOKEN (>=32 chars) and
temporarily enable AR3D_SCHOOL_STAGE_BOOTSTRAP_ENABLED=approved in Worker settings.
POST /v1/human/bootstrap with Authorization Bearer stage bootstrap token,
same Origin, and JSON email/password (new stage admin account). Bootstrap is
one-time; disable bootstrap flag and delete its token immediately.
Login, enable MFA, logout and sign in again with TOTP using existing stage auth
routes; safely store recovery codes. No production passwords/sessions copied.

- POST /v1/human/school-stage/seed with same-origin authenticated session and
  JSON {"confirm":"CREATE_ONE_FICTIONAL_SCHOOL_STAGE_TENANT"} creates a fixed
  fictional tenant, disabled author, School draft and frozen snapshot.
- GET /v1/human/school-stage/status returns snapshot, digest, script, review and
  flags to MFA Super Admin. Review fictional script manually.
- POST /v1/human/ai-flow-snapshots/<snapshotId>/review with configured tenantId,
  decision "simulation_reviewed" or "simulation_rejected", reason, and
  acknowledgeSimulationOnly:true. This is NOT live approval.
- Before enabling any provider flag, follow Phase 3E approval checklist: verify
  opted-in staff device, separate stage credentials, actual funding, real MP3
  quality, signed provider vectors, recording retention, carrier compatibility.
  A fixed fictional linear script is only a connectivity test, not customer
  admission qualification. No client campaigns or regulated industry calls.
